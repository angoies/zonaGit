    Linting¶

    1. YAML¶

    1.1. YAML (Genéricas)¶

    Estas herramientas verifican que el archivo esté bien formado (llaves, corchetes, espacios y tipos de datos).

    • yamllint: No solo busca errores de sintaxis, sino que comprueba reglas de estilo (longitud de línea, espacios sobrantes, etc.)

    • Instalación: pip install yamllint

    • Uso: yamllint mi_fichero.yaml

    • Online YAML Lint: Sin instalar nada, yamllint.com es la opción clásica.

    1.2. YAML Específica: Compose de docker¶

    Puede usar el propio comando de Docker Compose para validar la sintaxis y la configuración del fichero. Dependiendo de la versión, sería:

    docker compose config

    o

      docker compose -f docker-compose.yml config

    Este comando analiza el fichero, muestra la configuración resultante y detecta errores de sintaxis o configuración. Aquí no solo importa que el YAML sea válido, sino que cumpla con la especificación de Docker (nombres de imágenes, volúmenes, redes, etc.).

    1.3. YAML Específica: Action de GitHub¶

    Una de las recomendadas es actionlint, que es un linter especializado en workflows de GitHub Actions. Detecta errores de sintaxis, problemas de configuración y errores comunes en ficheros YAML de GitHub Actions.

    • GitHub: https://github.com/rhysd/actionlint
    • Prueba online: https://rhysd.github.io/actionlint/

    Además, puede combinarlo con herramientas generales de validación de YAML como yamllint, aunque estas no están especializadas en el esquema específico de GitHub Actions.

    Otra opción es utilizar act, que te permite simular la ejecución de los workflows localmente y así detectar posibles errores en el comportamiento, aunque su enfoque es más de simulación que de simple validación de sintaxis. https://nektosact.com/introduction.html

    1.4. Integración en el Editor (VS Code)¶

    Si usas Visual Studio Code puedes usar entre otras:

    1. YAML (Red Hat): Proporciona autocompletado y validación en tiempo real comparando tu archivo con esquemas de Kubernetes, Docker Compose y más.
    2. Docker (Microsoft): Añade IntelliSense específico para archivos .yml de Docker, reconociendo palabras clave como services, build, o environment.

    2. TOML¶

    Para los archivos TOML (Tom's Obvious Minimal Language), que se han vuelto muy populares gracias a herramientas como Rust (Cargo) y Python (pyproject.toml), también existen herramientas de validación.

    2.1. Herramientas basadas en Python¶

    Si ya tiene Python instalado, puedes aprovechar su soporte nativo o librerías específicas:

    • toml-lint: A linter for TOML files https://github.com/yaegassy/toml-lint

    • toml-validator: Una herramienta sencilla de línea de comandos.

    • Instalación: pip install toml-validator

    • Uso: toml-validator archivo.toml

    • tomli (o el módulo nativo tomllib en Python 3.11+): Puede validar un archivo rápidamente con un "one-liner" en la terminal:

    python3 -c "import tomllib; tomllib.loads(open('archivo.toml').read())"

    Si no imprime nada, es válido. Si hay error, lanzará una excepción indicando la línea.

    2.2. Integración en el Editor (VS Code)¶

    Para no depender de la terminal:

    1. Even Better TOML: Es la extensión más completa. Ofrece:
      • Validación de sintaxis en tiempo real.
      • Autocompletado.
      • Validación de esquemas (por ejemplo, te avisa si escribes mal una clave en un pyproject.toml).
    2. vscode-prettier-toml: Si ya usas Prettier, puedes añadir soporte para TOML instalando el plugin prettier-plugin-toml.
